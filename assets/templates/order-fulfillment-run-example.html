ยกเลิกการคำนวณ?

รายการจะเปลี่ยนเป็น 80_CANCELED และไม่ใช่ผลลัพธ์ปัจจุบัน แต่ message ที่ถูก worker รับไปแล้วอาจหยุดไม่ทันที
1 · เลือกขอบเขต

2 · ค้นหา

3 · คำนวณ / ยกเลิก
กดแล้วจะผ่าน prep-queue → mockr → mockc-queue → mockculator · Cancel ทำรายการเดิมเป็น 80_CANCELED
ข้อมูลทั้งหมดเป็น Dev/Test fixture ไม่มี PII · reload แล้ว reset · ปุ่ม mock ไม่ส่ง request, ไม่เขียน Oracle และไม่ส่งข้อความเข้า queue จริง

    สรุปสั้น ๆ

    สถานะนี้หมายถึงระบบกำลังซิงค์ข้อมูลเวลาทำงานหรือไฟล์ TRC ที่จำเป็นต่อการคำนวณเงินเดือนของรอบนั้น ก่อนจะไปโหลดข้อมูล order และข้อมูลพนักงานส่วนอื่น

    ข้อมูลเวลาทำงานมีผลต่อรายการที่คำนวณ เช่น รายได้ตามเวลาทำงาน การลา หรือรายการที่ต้องหัก ดังนั้นระบบจึงเริ่มเตรียมข้อมูลส่วนนี้ก่อนรวมข้อมูลจากแหล่งอื่น

    หมายเหตุ: ตรวจ cache ครั้งเดียวต่อ message/ชุดงาน

    ก่อนเรียก Sync ระบบคัดพนักงานรายคนจาก execution_employee โดยดู executionId, รายชื่อใน message และสถานะ 05_INITIATED จากนั้นจึงเรียก syncTimeRecordWithCache() เพียงครั้งเดียวต่อ message/ชุดพนักงาน

    • ตรวจอย่างไร: อ่าน Redis key คงที่ mockculator:sync-trc ผ่าน CacheManagerService.once() ซึ่งตั้ง TTL ไว้ 1,800 วินาที หรือ 30 นาที
    • พบค่าใน key: ถือเป็น cache hit ใช้ผล Sync เดิม และไม่อ่านไฟล์ S3/MinIO ซ้ำ
    • ไม่พบค่าหรือหมดอายุ: ถือเป็น cache miss เรียก syncTimeRecord() อ่านและบันทึกไฟล์ แล้วเก็บผลลัพธ์กลับเข้า key เดิม
    • ตรวจรายคน: row ของ TRC มี EMPLOYEE_UUID และถูกบันทึกลง emp_element_record หรือ emp_work_day_record การผูกนี้เป็นรายคน แต่ไม่ใช่เงื่อนไขตัดสินอายุ cache

    สรุป: สถานะและข้อมูล TRC ตรวจ/ผูกระดับรายคน ส่วนการตัดสินใจใช้ผล Sync ที่อายุไม่เกิน 30 นาทีเป็นการตรวจร่วมระดับ message/ชุดงาน เพราะ cache key ไม่มี employee หรือ execution อยู่ใน key

    จุดเริ่มต้นและจุดสิ้นสุด

    ลำดับการสื่อสารระหว่างส่วนที่เกี่ยวข้อง

    สถานะนี้เริ่มหลังจาก mockr รับชุดพนักงานจาก prep-queue และตั้งสถานะรวมของรายการเป็นกำลังเตรียมข้อมูล เมื่อซิงค์เสร็จ ระบบจะเข้าสู่การโหลดข้อมูลด้วยสถานะ 10_RUN_ALL_LOADERS

    ระบบทำอะไรในช่วงนี้

    • เริ่มงานซิงค์ข้อมูลเวลาทำงานที่ใช้กับรอบคำนวณ
    • ใช้ข้อมูลของรอบและบริบทการคำนวณที่อยู่ใน execution เดียวกัน
    • บันทึกเวลาที่เริ่มและจบช่วง loader/mock เพื่อใช้ตรวจสอบ performance
    • เตรียมข้อมูลให้ขั้นตอนโหลดข้อมูลและตรวจสอบพนักงานทำงานต่อได้

    ผลลัพธ์ทาง Business

    ผลลัพธ์ของขั้นนี้คือข้อมูลเวลาทำงานถูกนำเข้าสู่บริบทการเตรียมข้อมูลของรอบคำนวณ หากข้อมูลส่วนนี้พร้อม ระบบจะเดินหน้าต่อไปยังการโหลดข้อมูลที่ต้องใช้ในการคำนวณ
