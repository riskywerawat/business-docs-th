# Golden Examples

ตัวอย่างเอกสารอ้างอิงสำหรับเทียบ **ระดับความลึก** ก่อนส่งงาน

> ⚠️ เนื้อหาทั้งหมดในโฟลเดอร์นี้เป็น **ระบบสมมติเพื่อการสอน** (fictional demo system)
> ไม่ใช่เอกสารของระบบจริง ห้ามคัดลอกตัวเลข ชื่อระบบ หรือ flow ไปใช้กับงานจริง
> ใช้เป็น reference เรื่อง _ความลึก, โครงสร้าง, การเขียน caption, ระดับ evidence_ เท่านั้น

| ไฟล์             | ใช้เทียบกับ      | ความยาว                    |
| ---------------- | ---------------- | -------------------------- |
| `lite/README.md` | งาน level `lite` | ~110 บรรทัด อ่านจบ ~5 นาที |
| `full/README.md` | งาน level `full` | ~330 บรรทัด ครบทุกหัวข้อ   |

ทั้งสองไฟล์เป็น feature เดียวกัน (**การยื่นคำขอเบิกค่าใช้จ่าย**) เพื่อให้เทียบความต่าง
ของสองระดับได้ตรง ๆ — lite ตัดหัวข้อที่ยังไม่จำเป็นต่อการเข้าใจ flow,
full ใส่ครบทุกหัวข้อที่ trigger ตรง พร้อม evidence แบบ traceable

## วิธีใช้

1. อ่าน `full/README.md` เพื่อดูมาตรฐานความเนียบที่โหมด `full` ต้องได้
2. อ่าน `lite/README.md` เพื่อดูว่า "กลาง ๆ พอใช้" หมายถึงขนาดไหน
3. ก่อนส่งงาน ให้เทียบเอกสารที่ทำกับตัวอย่างของ level นั้น ถ้าหยาบกว่าชัดเจนให้แก้ก่อน

สิ่งที่ตัวอย่างทั้งสองแสดงให้เห็น:

- metadata หัวเอกสาร + ประวัติการแก้ไข
- การใส่ค่า enum จริงคู่คำไทย เช่น `PENDING_APPROVAL (รออนุมัติ)`
- การเขียน caption ใต้ diagram ว่าผู้อ่านต้องสังเกตอะไร
- การระบุที่มาของตัวเลขและค่าคงที่ (config key, enum, line reference)
- การเลือกหัวข้อ: full มีหัวข้อ Queue/Failure เพราะมี producer/consumer จริง
  ส่วน lite ยังคงหัวข้อ Queue เพราะเป็นหัวใจของ flow แต่ลดรายละเอียดลง
- การใช้ placeholder แทนข้อมูลจริง (`<employee-id>`, `https://api.example.com`)
